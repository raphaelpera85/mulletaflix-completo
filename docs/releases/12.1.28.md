# MulletaFlix Server 12.1.28 — validação de integridade antes do restore

## Correções

- A restauração do backup calcula e confere CRC-32 e comprimento das entradas ZIP antes de verificar capacidade de armazenamento ou gravar qualquer arquivo. Arquivo corrompido ou truncado é rejeitado antes de sobrescrever a configuração existente.
- Teste de regressão verifica que ZIP corrompido lança `InvalidDataException` e preserva o arquivo de configuração preexistente, sem criar diretórios de dados ou raiz restaurados.
- A auditoria do backup integral foi atualizada para distinguir a integridade física do ZIP da cobertura semântica ainda parcial.
- O builder do ZIP atualizador agora normaliza `-OutputDir` relativo para um caminho absoluto antes de entrar na pasta temporária. Isso corrige a falha de publicação observada no primeiro empacotamento com destino relativo.

## Validação

- `FullSystemBackup` Release: 33/33 aprovados, 0 falhas e 0 ignorados.
- `Jellyfin.Server.Implementations.csproj` Release: build concluído com 0 erros; quatro avisos XML preexistentes em projetos referenciados.
- Scripts Node de release/packaging: 23/23 passaram; novo teste de caminho `OutputDir`: 1/1.
- Builder Windows e Linux produziram os três pacotes. Conteúdo conferido no ZIP e tar.gz; SHA-256 e tamanho registrados abaixo.
- `npm ci`: 1.076 pacotes instalados; auditoria informou 12 vulnerabilidades (1 moderada, 11 altas). Build Vite terminou; emitiu avisos existentes de diretivas `use client`, imports/códigos de módulos e chunking.
- Testes de integração com produção, banco remoto, host Linux nativo, instalação limpa e restore completo de todos os componentes não foram executados nesta homologação.

## Limitações conhecidas

- O backup geral ainda não incorpora todos os contextos relacionais, bancos IntroSkipper ou coleções MongoDB Nebula identificados pela auditoria. A pré-validação CRC não equivale a cobertura integral nem a restore transacional.
- CI GitHub e homologação em instalação/produção permanecem gates separados.
