# MulletaFlix Server 12.1.29 — backup Nebula respeita coleção de tokens configurada

## Correções

- O backup Nebula para Supabase agora exporta todos os documentos da `BotTokensCollection` configurada, em vez de sempre consultar `bot_tokens`.
- A restauração do Supabase e a importação de tokens remotos também gravam na mesma coleção configurada. `bot_tokens` continua sendo o padrão compatível.
- A regressão exercita backup e restore para a coleção padrão e para uma coleção customizada, preservando tokens habilitados/desabilitados.

## Validação

- Suíte focal `NebulaSupabaseBackupBotTokensMongoTests`: 2/2 aprovados, 0 falhas/ignorados, com MongoDB 8.3.7 descartável limitado a `127.0.0.1:27099`.
- Suíte `FullyQualifiedName~Nebula` do projeto `Jellyfin.Server.Implementations.Tests`: 730/730 aprovados, 0 falhas/ignorados, com fixture Mongo descartável local.
- Frontend de produção: `tsc --noEmit` passou; Vite transformou 5.097 módulos. Persistem avisos Vite conhecidos e `npm audit` reportou 12 vulnerabilidades (1 moderada, 11 altas), sem ajuste de dependências nesta correção.
- Contratos Node de release/packaging: 23/23 passaram.
- Stage Windows validado pelo builder; ZIP atualizador inspecionado (3.364 entradas) e contém executável, web e worker/lock Nebula. O tar.gz Linux contém servidor, instalador e conteúdo Nebula esperado.
- CI remota, instalação limpa/upgrade, Linux nativo, APIs reais de Supabase/Telegram, mídia real e produção não foram homologados nesta execução.

## Limitações

- O backup geral continua parcial: esta alteração cobre a coleção de tokens no fluxo Supabase Nebula, não todos os contextos EF, IntroSkipper ou coleções Mongo. Ver `docs/backup-coverage-audit.md`.
- Nenhuma instalação/reinício ou alteração de dados em produção foi feita.
