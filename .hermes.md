# Mulletaflix

> The Free Software Media System — fork of Jellyfin/Emby, built on .NET 10

---

## Visão Geral

**MulletaFlix** é um servidor de mídia open-source (GPL-2.0) que permite gerenciar e transmitir sua biblioteca de mídia. É uma alternativa livre ao Emby/Plex, descendente do Emby 3.5.2 e portado para .NET para suporte cross-platform completo.

**Repositório principal:** `MulletaFlix-master/` (solução .NET `MulletaFlix.sln`)

## Build & Run

### Pré-requisitos
- **.NET 10 SDK** (ver `global.json`)
- **ffmpeg** (via `MulletaFlix-ffmpeg` ou sistema)

### Comandos úteis
```bash
# Build completo
dotnet build MulletaFlix.sln

# Run server (com web client embutido)
cd MulletaFlix-master
dotnet run --project MulletaFlix.Server --webdir /path/to/MulletaFlix-web/dist

# Run sem web client (dev frontend separado)
dotnet run --project MulletaFlix.Server --nowebclient

# Tests
dotnet test MulletaFlix.sln

# Build installer (Windows)
.\build-installer.sh
# ou
.\build-mulletaflix-installer.ps1
```

### Portas padrão
- **Server:** `http://localhost:8096`
- **Swagger/API docs:** `http://localhost:8096/api-docs/swagger/index.html`

## Regras para Hermes neste Projeto

### Build & Qualidade
- **Sempre** rode `dotnet build` antes de declarar mudança concluída
- **Sempre** rode `dotnet test` para mudanças em lógica de negócio
- Use `dotnet format` para formatação (EditorConfig presente)
- Respeite `Directory.Build.props` e `Directory.Packages.props` para versões centralizadas

### Estilo .NET
- `pathlib.Path` → `System.IO.Path` / `FileInfo` / `DirectoryInfo`
- Nullable reference types habilitados (`<Nullable>enable</Nullable>`)
- Prefira `async`/`await` sobre `.Result` / `.Wait()`
- Use `ILogger` (Microsoft.Extensions.Logging), não `Console.WriteLine`

### Arquitetura
- Controllers em `MediaBrowser.Controller` → Services em `MediaBrowser.Server.Implementations`
- Providers de metadata herdam de `BaseMetadataProvider` / `ILocalMetadataProvider`
- Plugins: implemente `IPlugin` e registrem via `PluginManager`

### Git / Commits
- Commits semânticos (feat, fix, refactor, docs, test, chore)
- Branch naming: `feature/...`, `fix/...`, `refactor/...`, `chore/...`

### AG Kit Usage
- Use `/plan` para quebrar tarefas complexas
- Use `/verify` para provar que código funciona (roda testes/build)
- Use `/orchestrate` ou `/coordinate` para tarefas multi-agente
- Skills carregam automaticamente via `when_to_use` — não force carregamento manual
