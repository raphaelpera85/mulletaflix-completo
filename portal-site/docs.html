Documentação do MulletaFlix

Tudo o que você precisa para instalar, configurar e operar seu servidor de mídia pessoal, conectar seus clientes e manter sua biblioteca organizada.

Visão geral: o servidor Linux ou Windows centraliza autenticação, bibliotecas e reprodução. O navegador, o Android e os clientes em evolução funcionam como interfaces conectadas a esse servidor.

Comece aqui

Primeiros passos

Para uma instalação nova, escolha Linux (Debian/Ubuntu x64) ou Windows e siga a sequência da plataforma:

Baixe e instale

Use o pacote Linux ou o instalador EXE da página de downloads. No Linux, execute o instalador incluído no pacote com privilégios administrativos.

Abra o servidor

Inicie o serviço MulletaFlix e acesse http://localhost:8096. Na primeira execução, crie a conta administrativa.

Adicione a primeira biblioteca

Escolha o tipo de conteúdo e a pasta que contém seus arquivos. Garanta que a conta do serviço tenha permissão de leitura. Aguarde a varredura e revise títulos, capas, áudio e legendas.

Conecte seus dispositivos

No Android ou no navegador, informe o endereço do servidor e entre com a conta criada.

Instalação Linux e Windows

Instalar ou atualizar

O servidor v12.1.0 oferece Linux x64 (Debian/Ubuntu com systemd) e Windows x64. Escolha o procedimento correspondente.

Linux — instalação nova

Baixe mulletaflix_12.1.0_linux-x64.tar.gz, extraia o arquivo e execute sudo ./install.sh dentro da pasta extraída. O instalador prepara MariaDB, FFmpeg, o usuário do serviço e o serviço systemd. Requer Debian/Ubuntu x64 com systemd e acesso à internet para instalar dependências.

Linux — serviço e dados

Gerencie com sudo systemctl status mulletaflix, sudo systemctl restart mulletaflix e sudo journalctl -u mulletaflix -f. A aplicação fica em /opt/mulletaflix/server; dados e configuração ficam em /var/lib/mulletaflix e /etc/mulletaflix/server.env. Configure caminhos de mídia legíveis pela conta mulletaflix.

Windows — instalação nova

Baixe o instalador mulletaflix_<versão>_windows-x64.exe. Execute-o na máquina que armazenará as mídias e siga o assistente inicial.

Windows — atualização

Use mulletaflix-update-win-x64.zip somente depois de ler as notas da release. Faça backup e não substitua uma instalação ativa sem conferir os passos do pacote.

Primeiro endereço

Depois de iniciar o serviço, abra http://localhost:8096 no computador servidor. Em outro dispositivo da rede, use o IP local do servidor e a mesma porta.

Pacote Android

O APK é publicado em uma release separada. Instale apenas o arquivo obtido na página oficial de downloads e conecte-o a um servidor que você controla ou autorizou.

Importante: o instalador Linux configura uma instância MariaDB local e credenciais próprias. Antes de migrar uma instalação existente, faça backup e planeje a migração dos dados; ele não importa automaticamente o banco de outra instalação. Para desenvolvimento, consulte o README do repositório para SDK .NET, Node.js, npm, Android Studio/JDK e comandos de cada componente.
Assistente inicial

Configuração pós-instalação

Após a primeira abertura, conclua estes passos antes de compartilhar o endereço com outros usuários:

Crie a conta administrativa

Use uma senha exclusiva. Essa conta controla bibliotecas, usuários, tarefas, reprodução, marca e estado do servidor.

Defina as bibliotecas

Adicione caminhos que o serviço consiga ler e escolha a categoria correspondente. Evite cadastrar a mesma pasta-pai e subpastas como bibliotecas duplicadas.

Teste uma mídia pequena

Valide catálogo, capa, áudio, legenda e reprodução antes de importar toda a coleção. Isso separa problemas de configuração de problemas do arquivo.

Verifique a saúde

Em uma instalação local, confirme /health e /ready no servidor. Em caso de falha, consulte os logs antes de alterar a configuração.

Administração

Configuração do servidor

Conta administrativa

Use uma senha exclusiva e forte. Crie usuários separados para as demais pessoas e conceda somente as permissões necessárias.

Pastas de mídia

Prefira uma pasta por biblioteca e evite misturar arquivos temporários, downloads incompletos ou backups com o acervo.

Metadados

Após a primeira varredura, revise o provedor de metadados, nomes de arquivos, imagens, favoritos e histórico.

FFmpeg

Configure o FFmpeg somente quando precisar transcodificar. A reprodução direta consome menos CPU e preserva melhor a qualidade.

Organização

Bibliotecas e nomenclatura

Uma estrutura consistente ajuda o catálogo a identificar os conteúdos e reduz correções manuais.

D:\Midia\Filmes\Nome do Filme (2024)\Nome do Filme (2024).mkv D:\Midia\Series\Nome da Serie\Season 01\Nome da Serie - S01E01.mkv D:\Midia\Musica\Artista\Album\01 - Faixa.flac

Use nomes estáveis, mantenha temporadas separadas e, quando necessário, inclua o ano no nome do filme. Depois de reorganizar arquivos, execute uma nova varredura.

Conectividade

Rede e segurança

Na rede local, use o IP privado do computador servidor. Para acesso externo, prefira uma VPN ou proxy reverso com HTTPS.

Não exponha uma porta HTTP simples diretamente à internet. Use firewall restritivo, senhas fortes, atualizações e um domínio com certificado TLS quando houver acesso remoto.

Rede local

Teste primeiro pelo endereço local e confirme que o firewall do Windows permite o tráfego necessário.

Acesso remoto

Configure VPN ou proxy reverso, valide o certificado e teste fora da rede Wi-Fi antes de compartilhar o endereço.

Player

Reprodução e transcodificação

O MulletaFlix tenta reproduzir diretamente sempre que o dispositivo suporta o formato. Quando não suporta, o servidor pode converter o conteúdo com FFmpeg.

Reprodução direta

Melhor desempenho e menor uso de CPU. Use formatos compatíveis com o dispositivo sempre que possível.

Transcodificação

Necessária para incompatibilidade de codec, resolução, áudio ou legendas. Monitore CPU, memória e espaço temporário.

Áudio e legendas

Selecione a faixa no player. Se uma legenda exigir queima no vídeo, o custo de transcodificação pode aumentar.

Live TV e SyncPlay

Use Live TV quando os canais e o EPG estiverem configurados; o SyncPlay sincroniza a reprodução entre participantes.

Integração opcional

Nebula

Nebula amplia o servidor com operações de catálogo e arquivos STRM, transferência e streaming de arquivos e integrações com MongoDB, Telegram e Supabase. Não é obrigatório para usar o MulletaFlix.

Quando ativar

Ative apenas se você precisar de armazenamento remoto, ingestão de arquivos, STRM ou dos fluxos de backup da integração.

Serviços envolvidos

Dependendo do fluxo, podem ser necessários MongoDB, Telegram, Supabase e caminhos locais de monitoramento ou staging.

Segredos

API IDs, tokens, senhas, strings MongoDB, URLs STRM e chaves Supabase devem ficar fora do Git, das issues e dos logs compartilhados.

Documentação técnica

Use o runbook operacional do repositório para saúde, streaming, backup, restore e diagnóstico das rotas Nebula.

Abrir runbook
Segurança: o FTP/HTTP nativo do Nebula não oferece FTPS. Mantenha o listener em loopback ou rede confiável, prefira VPN/proxy TLS e não exponha FTP/HTTP em texto puro à internet.
Continuidade

Backup e restauração

Backup do Nebula não equivale a backup completo do servidor. Planeje separadamente os dados abaixo:

Estado do servidor

Configurações, banco MariaDB, usuários, bibliotecas e metadados precisam de uma estratégia própria.

Arquivos de mídia

O catálogo não substitui os arquivos originais. Mantenha cópias em outro disco, servidor ou destino confiável.

Estado Nebula

O backup automático para Supabase, quando habilitado, protege os dados Nebula suportados pela integração e tem intervalo configurável.

Antes do restore

Faça uma cópia do estado atual, valide o destino e confirme credenciais. Uma restauração pode substituir dados Nebula.

Perguntas frequentes

FAQ

O MulletaFlix hospeda minha mídia?

Não existe uma hospedagem central obrigatória. O servidor roda na infraestrutura que você configurar; o Android e a web são clientes conectados a ele.

Preciso do Nebula para usar o servidor?

Não. Nebula é uma integração opcional para fluxos de arquivos, STRM, streaming, MongoDB, Telegram e backups remotos.

Posso acessar fora de casa?

Sim, mas prefira VPN ou proxy reverso com HTTPS, autenticação forte e firewall restritivo. Não encaminhe uma porta HTTP simples diretamente à internet.

Por que uma mídia não aparece?

Verifique o caminho, as permissões de leitura do serviço, a categoria, a nomenclatura e execute uma nova varredura. Corrija a identificação do item quando o provedor de metadados escolher o título errado.

Quando ocorre transcodificação?

Quando o dispositivo não suporta o contêiner, vídeo, áudio ou legenda. Reprodução direta é preferível; legendas queimadas no vídeo podem exigir mais CPU.

Diagnóstico e suporte

Quando algo não funciona

Cliente não encontra o servidor

Confirme rede, IP, porta, firewall e o endereço digitado. Teste primeiro no navegador do mesmo dispositivo.

Vídeo trava ou perde qualidade

Verifique se há transcodificação, reduza a resolução, teste reprodução direta e confira CPU, memória e armazenamento temporário.

Envie um diagnóstico útil

Consulte as issues do GitHub e inclua versão, sistema, passos para reproduzir e logs sanitizados.

Nunca publique segredos

Remova tokens, cookies, senhas, URIs MongoDB/Supabase, URLs STRM autenticadas e dados pessoais antes de compartilhar qualquer log.
