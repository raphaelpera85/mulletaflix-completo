# MulletaFlix 12.1.52

## Correções

- IntroSkipper resolve o destino de `.strm` antes de chamar FFmpeg. `file:` usa caminho local do Windows; URIs de rede permanecem URIs. Duração de áudio usa fallback para duração do contêiner, caminho FFmpeg acompanha configuração atual do servidor e as análises simultâneas ficam limitadas a duas.
- GetAvatar usa `HttpClient` nomeado, valida redirects para o host esperado e o componente web usa o helper autenticado de URL de imagem.
- GetAvatar limita o download dos packs a 1 GiB e a expansão de imagens a 2 GiB. O asset público `Steam.zip` tinha 958.257.135 bytes nos metadados consultados; a importação completa desse pack ainda não foi executada.
- O instalador NSIS declara UTF-8 para textos em português, inclui campo protegido para token DuckDNS e botão para abrir a página oficial de DuckDNS.
- Os logs Debug do FFmpeg removem userinfo, query e fragmento das URLs, tanto ao iniciar processo como ao registrar saída não zero.
- Dependências de produção web foram atualizadas para eliminar os avisos auditáveis de produção. Ferramentas de lint ainda têm avisos moderados de desenvolvimento que exigem upgrade incompatível e permanecem pendentes.

## Limitações

- O instalador atualizado ficou em `.build/release-v12.1.52-public-base/build/installer-output-fresh/`. A cópia homônima em `dist/` ainda é o instalador anterior (SHA-256 `935266…4F51E6A`) e deve ser tratada como obsoleta. O instalador atualizado não foi executado ou instalado em host descartável; não instalar sobre o servidor em uso. O binário local não tem assinatura Authenticode.
- CI hospedada, instalação/upgrade reais, primeiro scan da biblioteca e publicação permanecem pendentes. Android instrumentado e iOS não foram homologados nesta release.
- O build do tray usou o checkout limpo da dependência Windows em `f882f5f2ca7d84322f90b647114667273ee08b21`, disponível no ambiente local; a release pública 12.1.51 não fixa esse commit como gitlink no repositório principal.
- O resolver aceita `file:` e não restringe o destino às raízes de biblioteca. Se usuários não confiáveis puderem adicionar `.strm` a uma biblioteca analisada, o FFmpeg poderá tentar ler arquivos locais acessíveis à conta do servidor; a implantação deve confiar apenas em `.strm` controlados até haver validação do limite de biblioteca.
